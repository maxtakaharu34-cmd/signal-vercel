# Runtime architecture

Next-compatible Vinext server with the supported Sites integration. Pages are generated by scripts/build-pages.mjs from the independent dashboard components; source CSS is web/app.css and calculation modules are web/lib/. The build emits dist/server and dist/client for the same existing Site project.

Server-only ChatGPT identity is read with app/chatgpt-auth.ts. app/api/[...path]/route.ts sends trusted identity and runtime bindings to server/site-api.mjs. That module validates identity, owner scope, Origin and a signed administrator session before publishing. The browser never selects its own role or trusted actor.

The public index is synthetic and global. The server calls a narrowly scoped Supabase RPC with a random 256-bit capability that is absent from browser code. PostgreSQL stores only its SHA-256 digest in an inaccessible private table. The privileged implementation lives in a private schema with an empty search path; the exposed wrapper is SECURITY INVOKER. Other private functions/tables keep their existing restricted grants.

The bridge requires the capability for every operation, authorizes the owner for publication, validates checkpoint/signal input and checks the expected version. HTTP 409 prevents stale overwrites. Database triggers write the trusted Site actor ID and actual applied settings into the private audit log. Returned viewer history excludes actor identities.

The Site's current public audience is preserved. GET /api/scene, /api/events and /api/live-config expose only the common synthetic presentation and redacted event details; public reads use a fixed viewer actor and cannot choose a role. All other endpoints still require Site identity, and publication additionally requires the owner and a signed entry session. Native Site service access is independent of visitor identity; automated checks use a separate secret capability header in addition to connector-issued Site access. That header is never emitted to browsers.

The browser receives content-free WebSocket invalidations and fetches server-authoritative records. Notifications never carry scene data or credentials; untrusted hints are coalesced to at most four reads per second. Periodic reads recover from missed notifications. Continuous generation runs while the admin is open; it is not an unattended market engine. The earlier personal Supabase workspace APIs are preserved as compatibility data, not used for the new entry flow.
